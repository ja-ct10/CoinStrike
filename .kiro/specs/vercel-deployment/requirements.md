# Requirements Document

## Introduction

This document specifies the requirements for deploying the CoinStrike web version to Vercel using the Vercel CLI. The deployment system must handle the pygbag-generated web build files, configure proper CORS headers for WebAssembly execution, optimize game performance for web browsers, customize the loading experience, and ensure stable gameplay without freezing or lagging.

## Glossary

- **Vercel_CLI**: The command-line interface tool for deploying projects to Vercel hosting platform
- **Pygbag_Build**: The web build output generated by pygbag (Pygame WebAssembly build tool) containing index.html, .apk, and .tar.gz files
- **Deployment_System**: The complete deployment workflow including file preparation, configuration, and CLI execution
- **Loading_Page**: The initial screen shown to users while the game assets are downloading and initializing
- **Game_Performance**: The frame rate, enemy count limits, and particle effect limits configured for web execution
- **CORS_Headers**: Cross-Origin-Embedder-Policy and Cross-Origin-Opener-Policy headers required for SharedArrayBuffer and WebAssembly
- **Web_Build_Directory**: The vercel-deploy/ folder containing all files needed for Vercel deployment

## Requirements

### Requirement 1: Vercel CLI Deployment Execution

**User Story:** As a developer, I want to deploy the game to Vercel using the CLI, so that I can publish the web version with a single command.

#### Acceptance Criteria

1. WHEN the developer runs `vercel --prod` from the Web_Build_Directory, THE Deployment_System SHALL successfully deploy all files to Vercel production
2. WHEN deployment completes, THE Vercel_CLI SHALL return a production URL in the format `https://[project-name].vercel.app`
3. THE Deployment_System SHALL preserve all file types including .html, .apk, .tar.gz, .png, and .json during upload
4. WHEN deployment encounters errors, THE Vercel_CLI SHALL display descriptive error messages indicating the failure reason
5. THE Deployment_System SHALL complete deployment within 5 minutes for the full 248MB archive files

### Requirement 2: WebAssembly CORS Header Configuration

**User Story:** As a developer, I want proper CORS headers configured, so that the WebAssembly game executes without security errors in browsers.

#### Acceptance Criteria

1. THE Deployment_System SHALL configure Cross-Origin-Embedder-Policy header with value "require-corp" for all routes
2. THE Deployment_System SHALL configure Cross-Origin-Opener-Policy header with value "same-origin" for all routes
3. WHEN a browser requests any file, THE Vercel_CLI SHALL serve responses with both CORS headers present
4. WHEN the game loads in a browser, THE browser console SHALL NOT display SharedArrayBuffer or cross-origin isolation errors
5. THE vercel.json configuration file SHALL define header rules that apply to all paths matching "/(.\*)"

### Requirement 3: Static File Serving Configuration

**User Story:** As a developer, I want all game files served as static assets, so that the deployment uses Vercel's optimized static hosting.

#### Acceptance Criteria

1. THE Deployment_System SHALL use @vercel/static builder for all files matching "\*\*" pattern
2. WHEN a user requests index.html, THE Deployment_System SHALL serve it as the root document
3. WHEN a user requests coinstrike.apk or coinstrike.tar.gz, THE Deployment_System SHALL serve the files with correct MIME types
4. THE Deployment_System SHALL serve favicon.png with image/png content type
5. THE Deployment_System SHALL configure routes to map "/(.\*)" requests to "/$1" destinations

### Requirement 4: Game Performance Optimization for Web

**User Story:** As a player, I want the game to run at 60 FPS on web, so that gameplay feels smooth and responsive.

#### Acceptance Criteria

1. WHEN the game detects web platform (sys.platform == "emscripten"), THE Game_Performance SHALL set target frame rate to 60 FPS
2. WHEN the game loop executes, THE Game_Performance SHALL call clock.tick(60) to maintain 60 FPS timing
3. THE Game_Performance SHALL limit maximum concurrent enemies to 5 for web platform
4. THE Game_Performance SHALL limit maximum particle effects to 30 for web platform
5. WHEN performance drops below 50 FPS, THE Game_Performance SHALL maintain gameplay logic timing independent of frame rate

### Requirement 5: Custom Loading Page with Background Image

**User Story:** As a player, I want to see a custom loading screen with the game's background image, so that the loading experience matches the game's visual style.

#### Acceptance Criteria

1. WHEN the game initializes, THE Loading_Page SHALL display loading-page.jpg as the background image
2. THE Loading_Page SHALL display a progress bar showing download percentage from 0% to 100%
3. THE Loading_Page SHALL replace the default green box with a styled progress indicator
4. WHEN assets finish loading, THE Loading_Page SHALL hide automatically and transition to the game
5. THE Loading_Page SHALL center the progress bar horizontally and position it at 60% viewport height

### Requirement 6: Direct Menu Start Without Click Requirement

**User Story:** As a player, I want the game to start directly to the menu, so that I don't need to click before seeing the game interface.

#### Acceptance Criteria

1. WHEN all assets finish loading, THE Deployment_System SHALL bypass the "click to start" prompt
2. THE Deployment_System SHALL transition directly from Loading_Page to the game menu screen
3. THE Deployment_System SHALL NOT display "Ready to start! Please click/touch page" message
4. WHEN the menu appears, THE player SHALL be able to interact immediately without additional clicks
5. THE Deployment_System SHALL initialize audio context without requiring user gesture (or gracefully handle audio initialization on first interaction)

### Requirement 7: Stable Gameplay Without Freezing

**User Story:** As a player, I want the game to run continuously without freezing, so that I can play for extended sessions without interruption.

#### Acceptance Criteria

1. WHEN the game runs for 5 minutes, THE Game_Performance SHALL maintain consistent frame timing without freezing
2. WHEN the game spawns enemies, THE Game_Performance SHALL limit enemy count to prevent memory exhaustion
3. WHEN particle effects accumulate, THE Game_Performance SHALL prune old particles to maintain the 30-particle limit
4. WHEN the player collects coins or kills enemies, THE Game_Performance SHALL update game state without blocking the main loop
5. THE Game_Performance SHALL use asyncio.sleep(0) in the main loop to yield control to the browser event loop every frame

### Requirement 8: Deployment File Structure Validation

**User Story:** As a developer, I want the deployment to validate required files exist, so that incomplete deployments are caught before upload.

#### Acceptance Criteria

1. WHEN deployment starts, THE Deployment_System SHALL verify index.html exists in Web_Build_Directory
2. WHEN deployment starts, THE Deployment_System SHALL verify coinstrike.apk exists and is larger than 100MB
3. WHEN deployment starts, THE Deployment_System SHALL verify coinstrike.tar.gz exists and is larger than 100MB
4. WHEN deployment starts, THE Deployment_System SHALL verify vercel.json exists with valid JSON syntax
5. IF any required file is missing, THEN THE Deployment_System SHALL abort deployment and display an error message listing missing files

### Requirement 9: Deployment URL Configuration

**User Story:** As a developer, I want to configure the production URL, so that the game deploys to a predictable domain.

#### Acceptance Criteria

1. WHEN the developer runs `vercel --prod`, THE Vercel_CLI SHALL deploy to the production domain configured in project settings
2. THE Deployment_System SHALL maintain the existing project link to https://vercel-deploy-psi-lyart.vercel.app
3. WHEN deployment completes, THE Vercel_CLI SHALL display the production URL in the terminal output
4. THE Deployment_System SHALL update the .vercel/project.json file with the current project ID and organization ID
5. WHEN the developer visits the production URL, THE browser SHALL load the deployed game within 3 seconds

### Requirement 10: Pygbag Build Integration

**User Story:** As a developer, I want to rebuild the web version before deployment, so that the latest code changes are included.

#### Acceptance Criteria

1. WHEN the developer runs the build command, THE Pygbag_Build SHALL generate updated index.html, .apk, and .tar.gz files in the docs/ directory
2. THE Deployment_System SHALL copy all files from docs/ to vercel-deploy/ directory before deployment
3. THE Deployment_System SHALL preserve the loading-page.jpg asset during the copy operation
4. THE Deployment_System SHALL preserve the vercel.json configuration during the copy operation
5. WHEN the copy completes, THE vercel-deploy/ directory SHALL contain all files needed for deployment with no missing assets

### Requirement 11: Error Recovery and Diagnostics

**User Story:** As a developer, I want detailed error messages when deployment fails, so that I can quickly identify and fix issues.

#### Acceptance Criteria

1. WHEN deployment fails due to missing files, THE Deployment_System SHALL list all missing file paths
2. WHEN deployment fails due to network errors, THE Vercel_CLI SHALL display the HTTP status code and error message
3. WHEN deployment fails due to invalid vercel.json, THE Deployment_System SHALL display the JSON parsing error with line number
4. WHEN deployment fails due to authentication, THE Vercel_CLI SHALL prompt the developer to run `vercel login`
5. WHEN deployment succeeds but the game fails to load, THE Deployment_System SHALL provide a checklist of common issues (CORS headers, file sizes, browser compatibility)

### Requirement 12: Loading Page Progress Indicator Customization

**User Story:** As a player, I want to see accurate loading progress, so that I know how long to wait before the game starts.

#### Acceptance Criteria

1. WHEN assets download, THE Loading_Page SHALL update the progress bar percentage in real-time
2. THE Loading_Page SHALL display progress text showing "Loading X%" where X is the current percentage
3. THE Loading_Page SHALL style the progress bar with a visible border, filled portion, and background color
4. WHEN progress reaches 100%, THE Loading_Page SHALL display "Loading complete..." for 1 second before hiding
5. THE Loading_Page SHALL use the PressStart2P font for progress text to match the game's visual style
